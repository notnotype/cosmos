# ADR-0029：界面职责、版面骨架与视觉方向 v1

> 状态：Accepted design contract
>
> 日期：2026-09-24
>
> 关联：Proposal [`frontend-redesign-v1`](../proposals/frontend-redesign-v1.md)（accepted）与其分册（第 0 层产品结构、第 1 层视觉设计、V4 设计系统、E1–E7 工程决策）。前序：Proposal [`ui-surface-ownership-v1`](../proposals/ui-surface-ownership-v1.md)（accepted，信息架构）与 [`ui-surface-ownership/attempt-and-void-2026-09-15.md`](../proposals/ui-surface-ownership/attempt-and-void-2026-09-15.md)（上次失败记录）。被本 ADR 取代的视觉合同：[`neurobook-theme-system`](../proposals/neurobook-theme-system.md)（O1、O5）。PRD [`§8`](../requirements/0002-product-requirements/part-08-09.md)；架构 [`§11.4`](../architecture/0001-cosmos-foundation/part-07-12.md)；Task [`35-frontend-redesign`](../../.agents/tasks/35-frontend-redesign/README.md)

## Context

2026-09-15 的 Phase 2 真人验收提出两条界面问题（功能堆积在 Story 面板、文案过于专业化），`ui-surface-ownership-v1` 冻结了信息架构，但配套实现在同日被判定「布局有问题」并作废。作废记录把根因写得很明确：

> **版面骨架没被事先约定**：那次只冻结了「哪个操作放哪个页面」，导航与侧栏的跨页面位置、容器宽度与断点策略由 Agent 自行决定，结果导航落在页面下方、侧栏消失。

同时暴露第二个问题：**门禁对版面零覆盖**——浏览器验收只断言「点得通、文字在、无横向溢出」，从不断言导航与侧栏**出现在哪里**，所以版面回归对门禁不可见。

维护者 2026-09-24 指令「前端界面从 0 重新设计，技术栈底座仍为 React + Tailwind CSS」，按 [`docs/standards/frontend-design-process.md`](../standards/frontend-design-process.md) 走完第 0、1、1.5 三层后接受本设计。本 ADR 沉淀其中**稳定、反转成本高**的部分；逐页状态设计与实施细节留在 Task。

## Decision

### 1. 三层分工与「一个可写入口」

沿用 `ui-surface-ownership-v1` 已冻结的归属规则，本 ADR 确认其继续有效：

- **首页负责「看」、独立页面负责「管」、Story 页负责「读这一条」。**
- 归属判据：作用对象是这条 Story 且阅读时顺手要做 → 留 Story 页；作用对象是别的东西 → 去那个对象的页面；必须带上下文才能发生 → 入口留在上下文、管理集中到页面。
- **同一件事只保留一个可写入口**，不允许长期双写。
- **关联动作就地，创建动作去对象页**：Story 页可挂到已有话题、关联已有 Entity、打标签、收藏、写批注、固定到看板；「新建话题」「新建 Entity」「新建标签」「新建收藏夹」只在各自对象页。

### 2. 版面骨架：顶栏 + 悬浮侧栏常驻

```text
顶栏（常驻，不滚动）：品牌 · 全局搜索 · 服务状态 · 系统产出 · 外观 · 新建
悬浮侧栏（常驻，高度由内容撑开）：内容（首页看板/信息库/话题/Entity/系统产出）+ 管理（整理/自动化/设置）
主内容区（唯一滚动区）：居中限宽
```

- 顶栏与侧栏是**跨页面常驻框架**，切页不重建。由此在结构上排除上次的三类缺陷：导航不可能落在页面下方（它在框架层，不在页面网格里）、侧栏不可能在切页时消失、导航位置不可能随页面漂移。
- **唯一例外**：`/stories/:id` 隐藏左侧栏、保留顶栏与返回入口。理由：读一条内容的宽度优先，同时顶栏保证回程入口存在。**该例外必须有对应门禁断言**，否则会被误判为「侧栏消失」回归。
- 顶栏搜索框回车跳转 `/library?q=…`，**不放下拉结果面板**；完整筛选条件在信息库页展开。
- **顶栏底色 = 比画布底深一档的暖纸灰**（维护者 2026-10-03：先因「与页面底融为一体」取卡片白，
  再因「白色不好看」改为 `--surface-toolbar = color-mix(in srgb, var(--cosmos-shadow) 10%, var(--background))`，
  亮 `#deddd8` / 暗 `#121513`）。用主题感知的 `--cosmos-shadow` 染色，两套主题自动得到同一档关系；
  不加下边框——底色已足够区分，再画线是重复表达。

### 3. 路由：URL 层级 = 导航层级

```text
/  /library  /topics(/:id)  /entities(/:id)  /system  /organize  /automation  /settings  /stories/:id
```

八个导航项各占一层，`/:id` 只是详情，不产生第二层导航。整理页的五个分区用 query（`?tab=`）而非路径段——它们是同一页内的分区，不是独立页面。Story 采用**独立路由 + 独立页面**（非抽屉），因此可深链接、可刷新恢复、后退键语义正确。

### 4. 视觉方向：分层密度 + 单一强调轴

- **气质**：外壳仪器 + 阅读区书桌。两套密度由一条边界分开——**是否在读一条内容**。外壳 11–14 px 紧凑，阅读区 16–17 px 舒展。
- **颜色只编码信息**：8 个命名值（画布底、卡片面、正文、次要、强调、机器来源、错误、阅读面），无渐变、无装饰色块。强调色为墨绿（亮 `#2c5f4f` / 暗 `#64ab8f`）。
- **两个字族分工**：界面用系统无衬线栈，内容用衬线（标题与导语）；**中文正文用无衬线**，书桌感由行高与宽行距实现。不新增字体下载。
- **圆角两档**：控件 6 px、卡片 14 px。**阴影只给悬浮物**，内容面靠细线分隔。
- **动效只回应人的动作**：90/140 ms，无入场动画，`prefers-reduced-motion` 归零。
- **机器来源用独立语义**：`--marker` 只用于系统/Agent 产生的内容，与 `--primary`（人操作）分工，两者不互相替代。

### 5. Token 结构收成单一明暗轴

删除 `theme × colorway` 两套轴，改为单一 `data-cosmos-appearance="light|dark"`。「未来可安装第三方主题」已在 `neurobook-theme-system` 的非目标中排除，两套轴失去预留对象。

**V3 配色装进 shadcn 语义层**，因此现有 primitive 与 Cosmos 组件不需改 class：`canvas→background`、`surface→card`、`ink→foreground`、`graphite→muted-foreground`、`signal→primary`、`on-signal→primary-foreground`、`rule→border`、`alert→destructive`。只新增三个扩展语义：`--marker`、`--marker-soft`、`--paper`。

### 6. 断点：桌面三档，1024 px 是支持下限

| 断点 | 宽度 | 悬浮侧栏 | 主内容区 |
| --- | --- | --- | --- |
| 紧凑 | 1024–1279 px | 176 px | 自适应 |
| 标准 | 1280–1439 px | 196 px | 限宽 1080 px 居中 |
| 宽屏 | ≥ 1440 px | 196 px | 限宽 1080 px 居中 |

低于 1024 px 不做适配，显示「窗口过窄」提示。阅读卡片限宽 640 px **三档都不变**（行宽是阅读舒适度约束，不随屏幕变宽而放宽）。产品 PC 优先，不做移动端。

> **2026-10-01 实测修正（Task 35 切片 3e/4）**：上表按实施后的实测收敛为**一条不随档位变化的规则**——
> 悬浮侧栏固定 196 px，「侧栏 + 内容」作为**整体**限宽 1120 px 居中，主内容区 880 px。
> 两处偏离原文的理由都是实测：① 主区 1080 px 时信息库的竖排列表卡片宽高比到 7.4:1、
> 标题只占 350 px、七成横向空间是空白；② 「侧栏贴视口左边、只把内容在主区居中」在 1440 px 下
> 内容在视口里仍然偏右，所以改为整组居中。**「窗口过窄」提示按原文实现**（`< 1024 px` 隐藏外壳、
> 只留提示，不做降级布局）。三档与提示的实测断言在 `e2e/browser/layout-and-budget.spec.ts`。
>
> **2026-10-03 追加修正（Task 36，维护者指令）**：**悬浮侧栏整体等比放大 → 245 px**
> （先试 1.5 倍 = 294 px，维护者判定过大后收敛到 **`--nav-scale: 1.25`**，见 `globals.css`），
> 全部尺寸（宽度、内边距、行高、间距、字号、图标）都乘 `--nav-scale`。
> 只改 `font-size` 做不到等比——Tailwind 的 rem 值按根字号算，改根字号会波及全站；也不用
> `transform: scale()`，它会把焦点环与阴影拉伸发虚。整组限宽随之变 245 + 20 + 880 = **1145 px**
> （`(shell)/layout.tsx` 的 `max-w` 若仍是 1120 px 会压窄主内容，故同步放宽）；主内容区仍 **880 px**
> ——**行宽不随侧栏放大而变宽**（与决策 6 的行宽是阅读舒适度约束同一口径）。
> 门禁的 `SIDEBAR_WIDTH_PX` / `SHELL_MAX_WIDTH_PX` 已随之同步为 **245 / 1145**（前者是精确相等断言）。
>
> **2026-10-03 追加（Task 36，维护者指令）**：阅读页右栏加 **240 px 最小宽度**
> （`grid-cols-[minmax(0,3fr)_minmax(240px,1fr)]`）。按 3:1 算，1024 px 窗口下右栏只剩 199 px，
> 「标题」输入框被压成一条、下拉选项文字截断；下限只在窄档生效（1440 px 下右栏 282 px），
> 代价是窄档整组略超 80%、由左栏让位。维护者在「只加下限」与「左栏改自适应」之间选了前者。
>
> **2026-10-03 追加（Task 36）**：悬浮侧栏**跟随滚动**（`sticky top-[calc(4rem+2.5em)]`，
> 维护者指令）。top 取「顶栏 64 px + 顶栏下方间隔 2.5em」，正是侧栏未滚动时的位置，贴上不跳。
> 用 `sticky` 而非 `fixed`：仍留在文档流里，窄窗口下主内容被压缩的算法不变。
> **侧栏高度仍由内容撑开**，若导航项多到超过视口高度，底部会被裁——本 ADR 的 Revisit Gate 第 1 条
> 已登记该情况（届时评估固定高度 + 内部滚动）。

### 7. 实时更新：外壳级单条连接

SSE 连接与事件路由**提升到外壳层**，全程**恰好 1 条** `EventSource`；页面只订阅自己关心的 topic，不再全量重读。事件到 topic 有固定映射表，未映射的事件只更新连接状态。

**刷新边界**：列表页与未在编辑的详情页静默后台重读（保留滚动位置与筛选条件）；**详情页正在编辑时不覆盖**，显示「有新变化，重新读取？」由用户决定。

## Consequences

### 正面

1. **上次失败的两条根因被结构性堵住**：版面骨架成为可断言合同（不再由实施自由发挥）；门禁新增导航位置与侧栏存在性断言。
2. **换主题零改动的性质得以保留**：V3 配色装进既有语义层，现有组件不动。
3. **URL 层级与导航层级一致**，避免多页面项目最常见的技术债。
4. **`marker` 语义把「机器产出」变成可渲染的事实**，满足 PRD §9 UC-07 第 4 条对「区分 Agent 推断」的要求，且不必为 Phase 3 提前造面板。

### 代价与已知边界

1. **侧栏高度由内容撑开**（维护者明确选择）：八个导航项时约 370 px；**将来每增加一个导航项，卡片会长高、其下方内容位置随之变化**。若导航项数量增长到影响定位稳定性，再评估改为固定高度 + 内部滚动。
2. **Story 页隐藏侧栏**是本 ADR 引入的唯一框架例外，需要专门的门禁断言，否则会被读成回归。
3. **1024 px 以下不可用**：窄窗口只显示提示，不做降级布局。
4. **E7 的性能预算是设定值，尚未实测**（首屏可交互 ≤ 2 s、路由切换 ≤ 300 ms、首屏 JS 增量 ≤ 30 KB gzip）。未达标时按实测调整预算，不静默放宽。
5. **V1 线框与 V2 逐页状态设计未做**：骨架已冻结，逐页的空态/错误/加载文案在实施各页时确定。

### 对既有决定的影响

本 ADR 取代或修正以下既有合同，实施时须在对应文档留注记：

| 被取代 | 现决定 |
| --- | --- |
| `neurobook-theme-system` 的 NeuroBook 主题 + macOS 明暗配色 | 由本 ADR 第 4、5 条取代 |
| `neurobook-theme-system` 的 `theme × colorway` 两套轴 | 收成单一 `data-cosmos-appearance` 轴 |
| `ui-surface-ownership-v1` 的「Story 抽屉」措辞 | Story 改为独立页面（形状不变，容器改变） |
| 首页正文里的「信息库与搜索」页面级入口 | 独立页面 `/library` |
| `ui-surface-ownership-v1` 接受时未冻结的「新建标签留在 Story 抽屉」不对称 | 改为对称：标签与收藏夹都只在整理页新建 |

**未推翻**：三层分工、三个对象页的存在、归属规则、`ui-copy-review-v1` 已逐行裁定的术语表（`Story`/`Entity` 保留英文，其余用已定用户词）、单用户最大权限、PC 优先、「不做多语言 / 不引入 i18n 框架」。

## Revisit Gate

出现下列任一情况时重新审视本 ADR，而不是就地打补丁：

1. **导航项数量增长到改变侧栏高度会明显影响定位**（第 2 条的已知代价被触发）→ 评估固定高度 + 内部滚动。
2. **出现第二种界面语言的实际需求** → 从集中文案模块（`src/copy/messages.ts`）迁移到 i18n 框架；届时按当时需求决定，不预先引入。
3. **Phase 3 的 Workspace / Artifact 需要页面** → 另开 Proposal；本 ADR 不含这两个对象的页面设计。
4. **1024 px 以下的真实使用场景出现证据** → 重新评估支持下限与降级布局。
5. **E7 预算在真实数据下明显不可达** → 按实测调整并记录，不放宽后当作已达标。
6. **门禁对版面的断言实现后仍出现「导航/侧栏位置」类回归** → 说明断言覆盖不足，补断言而不是改合同。
