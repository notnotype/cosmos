# ADR-0032：模型缓存四价与两档整次计费

- 状态：accepted；决策者：Otirik；日期：2026-11-11。
- 配置、调用计价与 Web 已实现并通过本轮隔离验收；本 ADR 固定长期取舍，不代表部署或真实 Provider 外呼验收。

## Context

模型的普通输入、输出、缓存写入与缓存读取有不同单价，部分模型还要求输入超过阈值后整次请求改用高价档。原有输入/输出两价不能表达这些规则。用户已确认普通档加可选高档，不使用多档累进，并要求改价不能改变历史调用费用。

产品方案与弃选理由见[已接受 Proposal](../proposals/model-cache-tiered-pricing-v1.md)；字段、默认值、错误和重建验收由[公共合同](../spec/contracts/0001-public-contracts.md#模型定价与调用费用当前合同)拥有，本 ADR 不维护第二套 DTO。

## Decision

### 模型拥有币种与固定两档价格

每模型选择 USD 或 CNY，单位为该币种/每百万 token，不换汇；旧模型币种 USD。普通档与高档各使用四项 Decimal 价格显式列，另设阶梯开关和阈值，不使用 JSON 配置、独立档位表或通用计费框架。新建普通四价必填有限非负数，0 合法；启用阶梯必须阈值与高档四价齐全，关闭时阈值和高档四价为 null。

阈值在存储内部使用可空 BigInt，SQLite 迁移列必须声明为 BIGINT（整数存储）；公共 API 使用正安全整数 number，仓储负责 BigInt 写入与安全 number 读取。不能将迁移列声明退回 INTEGER 或使用 32 位 Int 映射，否则 Prisma 读回可超出映射范围；也不能在公开 JSON 中输出 BigInt。

### 按归一化总输入为整次请求选一档

普通输入、缓存读取、缓存写入是互斥用量；prompt 总输入为三者之和，输出不参与阈值。启用且总输入严格大于阈值时，该次调用普通输入、输出、缓存写入与缓存读取全部使用高档价格；否则全部使用普通档。阈值 272000 时，272000 为普通档，272001 为高档，不只对超出部分加价。一次调用使用同一份解析出的模型配置。

适配器消费 SDK 归一化后的计数，不重复从原始 prompt 加算缓存，也不采用 SDK 自带 cost 作为 Cosmos 费用真值。已核对 pi-ai 0.55.4 的两种 OpenAI provider：原始 prompt/input_tokens 包含缓存读取，归一化普通 input 扣除 cacheRead、cacheWrite 为 0。Cosmos 按互斥用量及用户配置自行计算，total 为四项费用之和。SDK 版本变化仍须重新核对计数映射，不能据当前 provider 的 cacheWrite 为 0 删除写缓存能力。

### 未知价格与历史费用保持原义

普通输入或输出价格未知始终省略整个 cost；缓存价格未知且对应非零用量时也省略，缓存用量为 0 则该项费用为 0。未知不得转换为已知零价。无效阶梯组合或费用溢出不产生部分总额。

旧模型保留原两价，新缓存价格 NULL 表示未知；新增调用输出完整用量与可计算的四项费用，公开缓存字段 optional 兼容历史。历史已持久化实际 cost 不随改价、换币种或公式更新重算，不补造旧记录缺失的缓存分项；候选持久 JSON 仍是该次实际费用的真值。

### 价格配置完整组替换

PATCH 涉及任何价格配置字段时，必须显式提交普通四价、币种、开关、阈值与高档四价的完整组，并沿用版本冲突检查；不从创建默认值或旧记录拼出混合价格档。只改名称等 metadata 时保留所有旧价和未知值，不强迫旧模型补缓存价格。保存配置不调用模型。

## Consequences

- 两档显式列让组合校验、读取回填和同次选档直接可审查；代价是第三档不能靠追加任意 JSON 自行生效。
- 用户看到的币种与所填价格一致；不同币种费用不能直接相加，汇率与跨币种汇总需要独立决定。
- additive 迁移保留旧两价和历史费用，缓存未知保持可识别；用户数据库迁移与部署仍需独立执行边界。回滚保留新列和数据并关闭阶梯，旧代码的缓存计价能力仍需单独评估，不能靠删除列或重算历史回退。
- 完整组 PATCH 增加客户端一次提交的字段量，换来价格档的一致性；metadata-only 路径维持旧记录可编辑。
- 费用是按 SDK 用量和用户配置计算的调用结果，不是服务商结算账单；无缓存预估与实际缓存调用保持独立语义。

## Revisit Gate

出现以下任一需求时重新评审本决定及迁移、公开合同和历史兼容，不预建通用 JSON 框架：

1. 第三档、任意多档、按超出部分累进或不同费用类别独立选档。
2. 汇率转换、跨币种合计、服务商账单对账或更严格的货币精度要求。
3. SDK/provider 改变输入与缓存计数关系，或新增不能映射到当前互斥四类的计费用量。
4. 价格需要独立生效时间、历史价格表或超出公共安全整数范围的阈值。

完整实施与分层运行证据见 [Task 42 本轮过程](../../.agents/tasks/42-default-model-ui-api/walkthrough.md)；短期测试数字不属于本 ADR。
