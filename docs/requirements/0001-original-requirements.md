> 1. 关于 Source，是否类似 github 的 action，既能用户手动触发，也能定时触发，也能自定义触发器（例如轮询检测邮箱，如果有新邮件则触发）。关于触发后应该执行的代码也是可以自定义的，甚至可以跑 agent。
> 2. RawObservation.url 这个字段，你需要考虑类似：消息来源于 Telegram、公众号、群聊这种。没有 url 的。
> 3. 系统应该是要维护一个信息库，这个信息库的原则是尽可能收集更多用户关注领域的信息。也就是说这个项目是信息聚合平台，用户不用亲自去花费时间去各个平台浏览。项目先去各个渠道收集信息（这可以使用各个平台的推荐系统 + 搜索系统），对应于用户自己操作的随意浏览阶段（项目相比用户自己来做，它能浏览更多信息，深度也更广，自定义程度也更高）。这是第一阶段，原始信息录入（把多个渠道的消息聚合，也就是信息录入后，本地项目离线也能访问已经录入的信息。需要存图片，这里我可以放宽为：“尽可能”）。信息库需要设计得非常灵活便于查询，分类、便签、BM5 这方面你可以考虑一下。
> 4. 经过第一阶段，信息库中存的一般都是与用户设定的注意比较相关的信息。对于这些信息，他们可能是这样的：
>    - 用户 BiliBili、X 等平台账号的主页推荐（可能每个小时就录入一批）
>    - 用户 BiliBili、X 等平台账号的关注用户（频率可能高一点）
>    - 某个网站的公告（靠触发器轮询）
>    - AIHOT 网站（去要去重）
>    - 邮件消息
> 5. 接下来就是考虑如何把这些信息展示给用户了。我觉得这个应用把消息展示给用户有两种：第一种是看板，另一种是推送。
>    - 看板需要展示：当前热点（热点可以是系统设置的，例如：DeepSeek API 状态追踪，或者是用户设置的，例如：XX 大会），精华消息（系统Agent精选过的信息，cosmos agent 通常会对这些主体进行深入。并且可以生成可视化的页面。例如：某一篇技术博客：LLM 先读一遍然后可以给出批注和观点。例如Agent 在信息库中发现了某一个竞品项目，自主进行深入调研产出报告。）。其他信息流（推荐系统，这一部分通常不用 LLM 参与。）总之看板界面的自定义程度很高
>    - 推送：考虑 Telegram、邮箱场景。目前先专注看板把。这个推送通常用于紧急消息、热点的推送
> 6. 目前系统中存在的实体：原始信息，话题（包含多个原始信息），精华（包含多个原始信息和多个话题，同时还带文件、附件、和可视化页面（数据形态可以给一个文件夹））（热点应该算精华的一种）（我觉得这些名字可能有点不太恰当）

## 2026-10-03：Story 阅读页版面放宽

> 我发现阅读页版面中，内容总宽还是太窄了。将内容总宽调整为屏幕大小的80%，居中。左右两栏宽度比3比1。

同轮交互确认（2026-10-03）：这是 Task 36 切片 A 的阅读页版面修正，取代维护者 2026-10-02 的「整组限宽 ≈931 px（左栏 34em）+ 左右 3:2」。三档断点（1024/1280/1440）都用 80% 与 3:1，1024 px 以下仍按 ADR-0029 只显示「窗口过窄」提示、不降级布局。

Agent 追问一项后维护者裁定：**正文跟着左栏自然撑满，不再限 34em**——即 V4 视觉规格里那条「行宽 ≤ 34em」的行宽合同在阅读页废止。Agent 已提示代价：大屏上正文行长达 ~1070 px（1920 视口实测，16 px 字号下每行约 67 个汉字），明显超过长文阅读的常用行宽上限，行尾回扫容易串行；维护者维持「撑满」。阅读页的现行取值与可断言合同以 [`docs/spec/interfaces/0005-web-client.md`](../spec/interfaces/0005-web-client.md) 为准，行宽合同的勘误记 [`frontend-redesign-v1.md`](../proposals/frontend-redesign-v1.md) 的勘误节，实施与门禁改动记 Task 36 的 walkthrough Round 3。

## 2026-10-03：阅读页右栏默认展开、收藏移入「编辑与关联」标题行

> 现在需要你改的：右栏默认展开，把收藏按钮放入”编辑与关联“标题行。

同轮交互确认（2026-10-03）：这是 Task 36 切片 A 的阅读页右栏修正，落在右栏 `StoryEditPanel` 上。① 「编辑与关联」的展开/收起状态**默认展开**（此前默认收起、要再点一次才出现表单）；② 收藏按钮从面板顶部独立一行移入「编辑与关联」标题行，与展开/收起按钮同一组。收藏仍然是全页唯一的收藏写入入口（ADR-0029 决策 1 的「同一件事只有一个可写入口」不变），只是位置从「面板顶部」变成「标题行右组」。

Agent 提示并记录的后果（维护者维持原选择）：右栏在 1024 px 档只有 199 px，「编辑与关联 + 收藏 + 收起」在标题行放不下时会换行——实测该档标题行高 64 px（标题一行 + 收藏/收起一行），1280 px 档为单行 28 px。实现与门禁改动记 Task 36 的 walkthrough Round 4；现行取值见 [`docs/spec/interfaces/0005-web-client.md`](../spec/interfaces/0005-web-client.md)。
