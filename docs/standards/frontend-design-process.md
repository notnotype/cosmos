# 前端界面设计流程

**版本** v0.4 · 2026-09-29
**状态** 生效
**适用范围** 从零开始设计前端界面（多页面产品 / 单页站点 / 组件级改动）

---

## 0. 适用判断（先做这一步）

本流程共四层、约 30 个步骤。**不先做适用判断，这份流程就没法用。**

| 场景 | 执行范围 |
|---|---|
| 多页面 / 多功能 / 有登录态 / 有路由 | 四层全做 |
| 单页落地页 / 作品集 | 第 0 层**只保留一张极简功能清单**（每段一行）；第 1 层保留 V3/V5/V6；第 1.5 层只做 E5/E6/E7 轻量版；第 2 层保留 I1/I2/I3 |
| 组件级 / 局部改动 | 只做第 1 层 V4/V5 + 第 2 层 I1/I2 |
| 改文案 / 单 owner bug / 配置问题 | 快速路径，无任何仪式 |

判断信号**不是文件数量**，而是：这个决定会不会改变产品行为、契约或架构边界。

不做轻/中/重三档预设，上表即全部裁剪依据。

---

## 1. 四层总览

```
第 0 层 · 产品结构     该有什么            ← 不可逆决策集中在这
第 1 层 · 视觉设计     该长什么样
第 1.5 层 · 工程决策   用什么做、怎么落地
第 2 层 · 实现与交付   做出来、验对、上线
```

---

## 2. 跨层原则

> **先业务后界面，先结构后视觉，先规范后开发，先 MVP 后迭代。**

制衡原则：

> **按比例裁剪，不为小项目做全套仪式。**

## 3. 第 0 层 · 产品结构

| 步骤 | 产出物 | 关键要求 | 技能 |
|---|---|---|---|
| **P0 项目目标与边界** | 项目目标、范围说明 | 解决什么问题、给谁用、成功指标、**哪些不做** | 无 |
| **P1 用户角色与核心场景** | 用户画像、场景清单 | 有哪些角色、在什么场景用、最核心的任务 | 无 |
| **P2 功能清单与优先级** | 功能列表、优先级 | 核心/次要/未来 + **MVP 边界** | 无 |
| **P3 竞品与参考分析** | 竞品分析、参考截图 | 同类产品如何设计流程/页面/交互，提炼可借鉴点 | 无 |
| **P4 信息架构设计** | 站点地图、信息架构图 | 内容分类、导航层级、菜单结构、**路由表（URL pattern）** | `information-architecture`（备选） |
| **P5 核心用户流程设计** | 流程图、任务流 | 登录/下单/发布/搜索等关键路径 + **状态清单** | Aegis `brainstorming`（`ui-workflow`） |
| **P6 页面清单与页面结构** | 页面清单、页面结构图 | 每页的**目标**、**模块区块**、跳转关系 | 部分覆盖，需人工补 |

### 顺序

**默认：P4 信息架构 → P5 用户流程 → P6 页面清单。**

本项目偏内容型，此顺序为正式默认。任务驱动型应用可把 P5 提到 P4 前，属例外处理。

无论哪种顺序，P4 与 P5 都要走一轮回路：拿 IA 回头验证流程，不通就改。

### 三处判据

**核心/次要/未来**
拿掉它，产品还能不能成立？不能成立 = 核心；能成立但体验明显变差 = 次要；不影响成立且本阶段不做 = 未来。分完写进**非目标**，否则会在实现阶段爬回来。

**状态清单（P5）**，共十项：

```
加载 / 空 / 部分 / 错误 / 成功 / 禁用 / 权限不足 / 取消 / 重试 / 边界情况
```

**路由表（P4）**
只画导航树不写 URL pattern 等于没定路由。导航层级与 URL 层级不一致是多页面项目最常见的技术债来源。

### P6 的两条性质

- **P6 是整条链的接口**：对第 1 层给出"要设计哪些页面"，对第 2 层给出"要建哪些文件、哪些路由"。
- **P6 有前置依赖**：页面结构依赖数据形状。不知道后端给什么字段，"模块区块"就是空中楼阁。需要与 **E3（接口与数据格式）** 来回一轮。

## 4. 第 1 层 · 视觉设计

| 步骤 | 产出物 | 关键要求 |
|---|---|---|
| **V0 brief 澄清** | 确认过的主题/受众/任务 | 见下 |
| **V1 低保真原型** | 线框图、可点击低保真原型 | 表达布局、层级、基本交互，**不纠结视觉细节** |
| **V2 交互细节与状态设计** | 交互说明、状态清单 | 把 P5 的十项状态逐一落实 |
| **V3 视觉风格方向** | 情绪板、风格稿 | 品牌调性、色彩、字体、间距、圆角、图标、插画风格 |
| **V4 设计系统与组件库** | Design Token、组件规范 | 按钮/表单/表格/弹窗/导航/卡片 |
| **V5 高保真确认** | 高保真稿、标注稿 | 基于组件与栅格，考虑不同状态与分辨率 |
| **V6 对着 brief 复审** | 修订后的方案 + 改动说明 | 抗默认自查，见下 |

### V0 说明

brief 没说清产品是什么 → 提出一个**具体主题 + 受众 + 页面的主要任务**交用户确认。

**提问纪律**：一次一个，优先选择题，每个问题过一道测试——"换一个答案，哪个设计边界会变？"不变就不问。

（部分已被第 0 层吸收。）

### V4 的 token 要求

| 维度 | 要求 |
|---|---|
| Color | 4–6 个**命名** hex 主色值 |
| Type | 字族及角色 + 明确字阶；1–2 个字族，两个必须明显可区分 |
| Layout | 一句话散文描述 + ASCII 线框图对比 + 明确对齐方式 |
| Principles | 这套系统凭什么独特的高层准则 |

### V5 的三种产出策略

| 策略 | 做法 | 选它的条件 |
|---|---|---|
| A 图优先 | 出 2–3 张高保真稿 → 对比选定 → 按稿实现 | 方向不确定、需人拍板、页面长 |
| **B 代码即稿**（默认推荐） | 只做 hero 区真代码 → 截图 → 定方向 → 铺满 | 方向大体清楚、单人决策 |
| C 直接实现 | 跳过稿，进 I1 | 仅当 brief 已钉死品牌 |

- 多页面场景**按页面类型各做一次**，不是全站一次。
- **退役规则**：设计稿是决策工具，不是交付物。实现并通过验证后归档，**不再作为后续修改依据**——否则它会变成第二个真相源。

### V6 抗默认自查

逐条问："换成任何同类页面，我会不会也这么写？"是 → 改，并说明改了什么、为什么。

对照五类当前 AI 生成设计的聚类特征：

1. 暖奶油底（近 `#F4F1EA`）+ 高对比衬线 + 陶土点缀（近 `#D97757`）
2. 近黑底 + 单一荧光绿或朱红点缀
3. 大报式细线分栏、零圆角、密集报纸栏
4. SaaS 卡片套装：相同圆角卡片、全站一个圆角值、同一个 `rgba(0,0,0,.1)` 阴影、渐变当装饰
5. 模板外壳：全大写 eyebrow、间隔号 meta 串（`A · B · C`）、`WORD — fragment` 破折号标签、`#0B0B0B` 冒充黑、等宽小标签、按钮挂 `→`

**限定**：这些不是禁令。brief 自己的措辞永远优先。反对的是"未经选择的默认值"。

## 5. 第 1.5 层 · 工程决策

本层属于设计流程的一部分，不独立成工程方案文档。E1–E7 的产出物与第 0、1 层的产出并列，同属一套设计交付物。

| 步骤 | 产出物 |
|---|---|
| **E1 技术选型** | 技术方案文档（框架、语言、UI 库、构建工具、状态管理、路由方案） |
| **E2 前端工程架构** | 脚手架、规范文档（目录结构、模块分层、公共能力、环境配置、CI/CD） |
| **E3 接口与数据格式约定** | 接口文档、Mock 数据（API 风格、字段、错误码、鉴权方式） |
| **E4 路由与权限体系** | 权限矩阵、路由表（页面路由、菜单权限、按钮权限、登录态、角色控制） |
| **E5 响应式与多端适配** | 适配方案（断点、布局策略、移动/桌面差异、是否适配小程序或 App） |
| **E6 可访问性与国际化** | 可访问性规范、i18n 方案（语义化标签、键盘操作、对比度、屏幕阅读器、多语言文案） |
| **E7 性能与安全预算** | 性能指标、安全策略（首屏时间、包体积、懒加载、缓存、图片优化、XSS/CSRF） |

**E3 与 P6 互为依赖**：数据形状决定页面区块，页面区块反过来约束接口设计。

**E7 是预算，不是优化建议**：在开发前设定指标，和事后调优是两件事。

## 6. 第 2 层 · 实现与交付

| 步骤 | 产出物 | 关键要求 |
|---|---|---|
| **I0 评审与排期** | 排期表、任务看板 | 设计评审、技术评审、拆分任务、里程碑、负责人 |
| **I1 开发实现与联调** | 可运行版本 | 先 Mock 后真实接口；见下约束 |
| **I2 自评收敛** | 收敛后的界面 + 笔记 | 见下 |
| **I3 测试与验收** | 测试报告、Bug 列表 | 功能/兼容性/响应式/性能/可访问性测试 |
| **I4 上线与监控** | 上线版本、监控看板 | 埋点、错误监控、性能监控、日志 |
| **I5 迭代优化** | 迭代计划、优化版本 | 按数据、反馈和线上问题持续优化 |

### I1 约束

- **Hero**：用主题世界中最具特征的东西开场。"大数字 + 小标签 + 统计数据 + 渐变点缀"是默认套餐，只有确实最优才用。
- **排版禁忌**：标题里只强调某一个词 / 标签用全大写 / 内容上方加多余排版标签。
- **结构装置**（描边、编号、分隔线、eyebrow）必须编码信息而非装饰。编号 `01/02/03` 只在内容真是序列时用。
- **动效**：一个精心编排的时刻胜过零散效果；每段 fade-and-slide-up、每张卡片 hover 过渡是通用默认。回应人操作的动效在能表明"什么变了"时受欢迎。
- 行宽默认 <80 字符；衬线正文行高略高。
- **CSS 特异性**：类型选择器 `.section` 与元素选择器 `.cta` 容易互相抵消，常见于 section 间距。
- **Tailwind v4 的边框默认色**：`border` / `border-t` / `border-b` 不带颜色类时，预检让它继承 `currentColor`，
  也就是**文字色**（实测 `borderTopColor: rgb(28,31,28)`），比 `--border` 重得多。分隔线必须显式写
  `border-border`，或直接用 `components/ui/separator.tsx` 的 `<Separator decorative />`。
  这条在 Task 36 Round 5 才被发现：当时全仓 38 处分隔线都在用正文墨色。
- **质量下限**（做到但不张扬）：移动端响应式 / 键盘焦点可见 / 尊重 `prefers-reduced-motion` / 对比度可访问。

### I2 动作

- **截图看**——"一图胜千 tokens"。
- **Chanel 原则**：出门前照镜子，摘掉一件配饰。只在一个地方花大胆，其余安静克制。
- **文案复审**：主动语态（"Save changes" 非 "Submit"）/ 动作全流程同名 / 用户视角命名 / 空态是行动邀请 / 错误不道歉不含糊。
- 记下这次试过什么，下次不重复。

### `impeccable` 使用须知

- **首次调用会下载引擎二进制**到 `~/.impeccable/bin/`。装完尚未触发，第一次跑之前需要知情。
- 每会话先跑一次 `<skill-base-dir>/scripts/impeccable context`；Windows 无 `sh` 时用 `impeccable.cmd`。
- 命令通过 `/impeccable <command> <target>` 调用，共 24 条（`init` / `shape` / `document` / `extract` / `critique` / `audit` / `polish` / `harden` / `onboard` / `adapt` / `optimize` / `clarify` / `distill` / `bolder` / `quieter` / `animate` / `colorize` / `typeset` / `layout` / `delight` / `overdrive` / `live` / `generate` / `craft`）。
- **`extract` 不是独立技能**，是主技能的第 5 条命令。仓库内只有 `impeccable` 一个可安装技能。
- 有独立检测器 CLI：`npx impeccable detect <path|url>`，61 条确定性规则，无需 LLM，可输出 JSON 进 CI。
- **DSH 不支持它的设计 hook**（仅 Claude Code / Cursor / Codex / Copilot / Grok 有），本环境只有技能、无自动扫描。
- **安全**：Socket 报 1 个 LOW 告警，位于 `scripts/modern-screenshot.umd.js`，属"能力面偏宽"而非恶意代码（无凭据窃取、后门、持久化、eval/exec）。触发条件是处理**不受信任的 DOM/CSS**或传入不受信任 options。**不要拿它指向不可信页面。**

## 11. 留档策略

**第 0 层不留档。** P0–P6 全部作为会话内工作产物，不产出 spec 文档。

### 后果

1. **跨会话丢失**：新会话开始时，功能分诊、IA、路由表的决策不在任何文件里，只能重新推导。而 P4 的路由表恰恰最不该重新推导。
2. **"非目标"无处安放**：§3 中"分完必须写进非目标，否则未来功能会在实现阶段爬回来"这一机制依赖有记录载体。没有文档，这条防线不存在。

### 缓解（待定）
